# ورشة — إدارة محل تصليح الهواتف

تطبيق عربي RTL لإدارة ورشة صيانة الهواتف، مع واجهة HTML/CSS/JavaScript خفيفة ومتجاوبة.

## وظائف لوحة الصيانة

- لوحة التحكم وإحصائيات التصليحات والأجهزة الجاهزة والمقبوضات وتنبيهات المخزون.
- استقبال الأجهزة، بيانات الزبون والجهاز والعطل، التشخيص والحالة والأسعار والدفعات والضمان.
- وصل استلام قابل للطباعة ورسائل واتساب بحالة التصليح.
- المخزون وقطع الغيار وطلبات الشراء والموردون.
- الزبائن والمصروفات والتقارير وإعدادات الورشة.
- تصدير واستعادة بيانات JSON.

## الإصدار متعدد الورش

أضيفت بنية أولية لتشغيل كل ورشة بحساب مستقل على Cloudflare Workers + D1:

- تسجيل ورشة جديدة باسم مستخدم وكلمة مرور؛ الاشتراك يبدأ بحالة «بانتظار التفعيل».
- كلمات المرور تُشتق باستخدام PBKDF2-SHA-256، ولا تُحفظ كنص صريح.
- جلسات عشوائية مخزنة بصيغة hash في D1، مع صلاحية محددة.
- بيانات مساحة العمل مخزنة في D1 حسب معرّف الورشة، وواجهة API لا تُرجع البيانات إلا لجلسة الورشة نفسها.
- تفعيل وتجديد الاشتراك يدويًا من لوحة الإدارة `admin.html`.
- حسابات الفنيين المتعددة مؤجلة إلى مرحلة لاحقة.
- البيانات المحلية القديمة لا تُرفع تلقائيًا؛ تظهر مطالبة صريحة قبل نقلها إلى حساب الورشة.

## نشر Cloudflare

يتطلب النشر إعداد حساب Cloudflare ومفتاح إدارة سريًا. لا تضع مفتاح الإدارة أو أي سر في ملفات الموقع أو GitHub.

1. ثبّت Node.js ثم شغّل `npm install -D wrangler` في نسخة محلية من المستودع، ثم `npx wrangler login`.
2. أنشئ قاعدة البيانات: `npx wrangler d1 create reparephone`.
3. تم إنشاء قاعدة D1 وربط معرّفها في `wrangler.toml`؛ تحقق من المعرّف إذا نشرت نسخة مستقلة.
4. طبّق مخطط قاعدة البيانات: `npx wrangler d1 migrations apply reparephone --remote`.
5. أنشئ مفتاح إدارة قويًا وفريدًا، ثم اضبطه كسرّ: `npx wrangler secret put ADMIN_KEY --name reparephone`. اختر قيمة طويلة وعشوائية واحفظها في مدير كلمات مرور؛ لا ترسلها في المحادثات ولا تضفها إلى Git.
6. راجع `ALLOWED_ORIGINS` في `wrangler.toml` إذا كنت ستستخدم نطاقًا مختلفًا.
7. انشر التطبيق: `npx wrangler deploy`.
8. عنوان API المنشور: `https://reparephone.imadtbn-prayer.workers.dev`؛ اختبر `/api/health`. يجب أن تظهر استجابة `ok: true` و`database: connected`.
9. افتح `/register.html` لإنشاء حساب ورشة، ثم `/admin.html` لتفعيل الاشتراك. أدخل مفتاح الإدارة عند الطلب؛ يُحفظ في `sessionStorage` لتلك الجلسة فقط.
10. من لوحة Cloudflare أو عبر Wrangler، استبدل سر `ADMIN_KEY` الذي أنشأ أثناء الإعداد بقيمة تختارها أنت، ثم افتح `admin.html` وأدخل القيمة الجديدة. اختبر حسابين منفصلين قبل نقل بيانات حقيقية. تأكد أن الورشة الأولى لا ترى أي سجلات للثانية.

ملف `assets/cloud-config.js` يستخدم عنوان الصفحة الحالية افتراضيًا؛ لذلك يجب فتح النسخة المنشورة من Worker لا من GitHub Pages القديم. GitHub Pages يظل نسخة ثابتة منفصلة ولا يوفر API أو مصادقة سحابية بذاته.

## ملاحظات تشغيل وأمان

- حدّثت تجزئة كلمات المرور لتستخدم 100,000 دورة PBKDF2 كحد متوافق مع Cloudflare Workers؛ تجاوز هذا الحد قد يفشل التسجيل قبل حفظ حساب الورشة. لا ترفع قيمة `PASSWORD_ITERATIONS` فوق هذا الرقم.
- يسجّل Worker الآن مسار الطلب ورسالة الاستثناء ومكدسه في سجلات Cloudflare لتسهيل تشخيص أخطاء الخادم، دون تسجيل بيانات النموذج أو كلمة المرور.

- الاشتراك النشط له تاريخ انتهاء؛ انتهاء الصلاحية يمنع الوصول إلى بيانات مساحة العمل حتى التجديد.
- مفتاح الإدارة محفوظ كـ Worker secret ويُرسل عبر HTTPS. لا تشاركه ولا تضعه في المستودع.
- احتفظ بنسخ احتياطية دورية واختبر استعادتها. لا توجد في هذه المرحلة مزامنة لحظية بين عدة تبويبات أو نظام تعارضات متقدم.
- واجهة النسخ JSON موجودة في لوحة الصيانة؛ لا ترفع نسخ الزبائن إلى مستودع عام.
- حسابات الفنيين، الدفع الإلكتروني، والتحقق بالبريد أو الهاتف خارج نطاق المرحلة الأولى.

## التشغيل المحلي

يمكن تشغيل نسخة الواجهة القديمة باستخدام `python3 -m http.server 8000`، لكنها لا توفر تسجيلًا سحابيًا ما لم تُنشر الواجهة مع Worker وتُهيأ قاعدة D1. لا تستخدمها لحفظ بيانات عمل حقيقية قبل إعداد الخادم.
